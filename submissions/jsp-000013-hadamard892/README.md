# Order-892 Hadamard matrix: formalization evidence

## English

This package concerns the finite order 892 of JSP-000013. The proved endpoint is
`Hadamard892.exists_hadamard892 : ∃ H : Matrix (Fin 892) (Fin 892) ℤ, Matrix.IsHadamard H`.
It does not solve the Hadamard conjecture for all positive multiples of four.

The Lean implementation formalizes the classical Goethals–Seidel construction
and supplies four explicit length-223 sign sequences. Mathematical discovery of
the input data is not claimed. Sources and reported mathematical attribution
are detailed in [ATTRIBUTION.md](ATTRIBUTION.md).

## Proof structure

- GenericGS.lean: general four-by-four block row-Gram theorem.
- CirculantBridge.lean: reflection, commutation and positive-shift correlation identities.
- GenericHadamard.lean: signs plus correlations imply the standard Matrix.IsHadamard predicate.
- Hadamard892Data.lean: explicit sign data, lossless bit encoding and entry signs.
- Hadamard892Certificate.lean: all 223 correlations computed by the Lean kernel.
- Hadamard892.lean: unconditional order-892 matrix and existence statements.

## Reproduction

The toolchain is Lean 4.34.0, with Mathlib pinned to
5ed2965256430c3649e86755f9576b54eca72435 and a complete dependency manifest.
Use `lake exe cache get` to obtain the matching Mathlib cache. The tested
reproduction command and checker setup are in [REPRODUCE.md](REPRODUCE.md).
The driver compiles all six local proof modules in dependency order from source,
runs `leanchecker --fresh`, exports the named theorem closures and checks them
with Nanoda. The complete run passed on 17 September 2026 UTC. Nanoda checked
9,340 declarations with no errors. All three exported roots use only `propext`,
`Classical.choice`, and `Quot.sound`; no additional axiom is permitted.

The run denied network access for every proof-checking command, with an actual
positive/negative network-policy control. It used precompiled pinned dependencies;
it did not rebuild all dependencies or isolate the filesystem. These are local
reproducibility checks, not an organizer-appointed verifier's signed record.
See [the receipt](verification/verification.json), [logs](verification/CHECK_LOGS.json),
and [tool provenance](verification/TOOL_PROVENANCE.json).

`NegativeControls.lean` is separate from the main proof's import closure. It flips
one sign, proves that all entries remain signs, and proves that the first nonzero
correlation is -4 rather than the required zero. Its successful compilation is
recorded separately in the logs; it is not part of the three-root Nanoda export.

The 41,120,305-byte proof export has SHA-256
`e9510f14f53a2fa9f1e2591cbda2708b8b72323c36175f97d2ca977898d62eb1`.
It is generated by the reproduction driver and retained with the submitter's
local evidence bundle. Permanent external archival is pending; the public
[artifact manifest](verification/ARTIFACTS.json) deliberately has no invented
archive identifier. Large artifacts are excluded from the awards repository.
